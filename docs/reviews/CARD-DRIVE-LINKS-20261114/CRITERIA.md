# Card document links acceptance

Baseline `01474948a2d9f3f49393c93e566f000167a84f5b` with the four already-deployed drawer files replayed from the November 14 UAT release. Scope is sensitive because shared card data and board authorization are involved.

- The card drawer has a separate Documents section before Comments, with named Google Docs, Sheets and Drive file links. A Drive file link can point to a PDF, Word document, or Excel workbook. An editor adds or removes links and uses the existing Save changes control. Authorized read-only roles can open saved links. Hide the section on an empty read-only card.
- Card GET and versioned PATCH are the only new link transport. Up to ten ordered, unique, strictly validated Google URLs and labels. Reject lookalike domains, untrusted schemes, user information, nonstandard ports, and Google redirect routes. Open on user action in a new tab with no opener or referrer. Flowboard stores the URL and display name only. Google controls access to file bytes. Neither backend nor drawer fetches the link or generates a preview.
- Use existing card board grants, CSRF protection, optimistic version, and idempotent retry. An omitted list preserves the current value and an explicit empty list clears it. Stale concurrent changes preserve the local draft and require review. Archived/trashed/revoked cards follow current card authorization. Activity shows that the link count or list changed without including any URL or label.
- Migration 0029 is additive and can apply directly after 0027. The native upload migration 0028 and scanner are deferred on a separate source branch and excluded from the links candidate. Existing cards begin with no links.
- Verify contract input cases, mounted disposable PostgreSQL roles, migration, update and replay, lost-response/draft and stale behavior, existing assignee/image regressions, and a real browser against the built drawer. Full independent review is required for backend closure. Hosted application and database changes require a separate UAT deployment step.

Local Chrome uses `scripts/e2e/card-drive-links.mjs` with the exported Pages app and the disposable `flowboard_ui_test` database. Build with `NEXT_EXPORT=true NEXT_DIST_DIR=.next-drive-export npm run build:web`. Set `NODE_ENV=test`, `FLOWBOARD_UI_TEST_DATABASE_URL` and `FLOWBOARD_DRIVE_BROWSER_RESULT` for the browser run. The harness intercepts the only intentional navigation to Google and supplies a synthetic page.

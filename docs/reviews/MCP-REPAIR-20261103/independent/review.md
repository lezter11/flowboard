# Round 1 independent acceptance review

**Verdict: fail. Weighted score 8.345/10.** The board-listing API still gives a boards-only credential the board description. The narrower column endpoint and MCP client remove extra fields, but a credential holder can call the permitted listing API directly. This contradicts the frozen metadata-only criterion and prevents closure, despite all required suites passing.

For example, a Flowboard Owner can give an assistant a credential to discover board names and columns. That credential should not also return the board's descriptive text under this task's agreed boundary. A runtime projection means constructing the actual outgoing object from permitted fields; a TypeScript type or a client-side filter does not remove data already sent by the server. A small PAT-specific response projection on every discovery route fits the existing API. A dedicated integration namespace is a future alternative with stronger organizational separation and additional maintenance cost.

- Entry: `apps/api/src/http/routes/boards.ts:144`, especially158-160. Capability: `apps/api/src/http/middleware/token-policy.ts:9`.

- Evidence: `adversarial-results.json`, `adversarial.log` exit1, and preserved executable probe. The failing assertion checks absence of `description`; it does not rely on an error message or a mocked adapter.
- Impact: violates the explicit discovery data boundary inside the otherwise authorized project. This is not a demonstrated cross-project leak or exposure of raw bearer values. Board descriptions can carry content excluded by the frozen acceptance wording.
- Counterevidence: `/boards/{id}/metadata` and `FlowboardClient.listBoards/getBoard` correctly project their output. They do not control a direct API caller. No criteria narrowing was accepted; the Architect independently agreed to preserve this failed round and fix the API.
- Fix: explicitly project a bounded metadata response for PAT board listing while preserving the existing session response; test both permitted discovery routes with real descriptions/cards/count sentinels and current grants. Submit a new immutable target and re-review.

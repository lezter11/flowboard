# Image validation scope and source fidelity

Architect decision before final independent scoring,2026-11-03. User delegated the best CMYK/conversion option. The candidate admits still PNG, RGB/grayscale JPEG (baseline/progressive) and bounded WebP animation. Direct CMYK/other JPEG component models return controlled422; the UI converts recognized unsupported color models and reports failure instead of silently uploading that original. No paid/native hosting service is introduced.

Checks are layered: bounded private uploads, MIME/container/chunk/CRC/dimension/frame controls, complete JPEG scan consumption, native streaming PNG zlib/scanline/filter completeness, and a complete runtime codec decode. The stream checker drains/discards pixels under backpressure, not a JavaScript canvas allocation. A single absolute8s preflight budget covers these phases; deterministic JPEG200M-operation fuel and per-isolate work admission remain separate resource bounds. Temporary JPEGquality1 decode output is discarded. Finalization promotes the already verified original private object by its database reference; stored bytes and hash do not change.

This is not a universal file-conformance, steganography or metadata-sanitization service. In particular, palette-index error recovery prescribed by the native codec is allowed: the [W3C PNG3 error-handling rules](https://www.w3.org/TR/png-3/#13Error-handling) require out-of-range palette indices to render as opaque black, while identifying that as an encoder error. Independent palette probes and strict native decoding agree on this recovery. We do not add a second JavaScript unfilter/color decoder solely to reject it. This bounded input-policy decision does not waive rejected zlib checksum/trailing-stream, row-length, filter, JPEG truncation or cross-project defects. No exfiltration or code execution was demonstrated for palette recovery. Native codecs must remain patched; metadata and opaque ancillary payloads remain untrusted.

Hosted acceptance is separate. Local workerd wall time does not prove Cloudflare Free CPU/memory or Images quota suitability. The actual UAT bucket currently has a staging/24h deletion rule; that exact rule must be removed and live-verified before promoting source that keeps referenced objects at those keys. Database cleanup owns their lifetime. Preserve multipart-abort policy and production untouched. Before/required config is recorded in `uat-storage-lifecycle-{before,required}.json`; no cloud mutation is claimed here.

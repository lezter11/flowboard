# ATT-02 full decoder options — 2026-11-03

**Actions / recommendation.** Keep the container repair, but do not close ATT-02: the explicit corrupt-DEFLATE probe is a genuine remaining implementation gap. The narrowest practical full-decoder design is a portable verifier interface with **Cloudflare Images raw-byte binding in Worker and pinned native sharp in Node**. It avoids expanding a 20MP image inside a 128MiB Worker isolate. This is an implementation recommendation, not authorization to create cloud resources, a deployed claim or independent approval. No dependency was installed for this assessment.

**Why and options.** Flowboard needs to distinguish a real image from an envelope that merely declares dimensions. A standard decoder must consume the compressed pixels; header metadata alone cannot prove this. The existing strict container/digest/dimension checks remain an inexpensive first pass.

| Option | Evidence and feasibility | Decision |
|---|---|---|
| Stock jSquash PNG/JPEG/WebP | Browser/Worker-oriented WASM with manual module initialization and limited Node support. Examined JPEG and WebP C++ allocate an RGBA buffer and construct a JS `Uint8ClampedArray` from its memory view. At 20,000,000 pixels, those two buffers alone are 160,000,000 bytes = 152.59MiB, before compressed input, WASM heap slack, runtime, or JPEG coefficient planes. | Not safe as a drop-in at the existing cap. Small compressed bundle size does not solve peak memory. |
| Validation-only custom WASM port | Remove JS pixel copy and return status/dimensions; scanline-discard baseline JPEG can be small. Progressive JPEG still requires persistent coefficients; Wuffs source explicitly retains sample planes and 16-bit coefficient planes. For 20MP three-component 4:4:4, those planes alone infer roughly 180MB in that implementation, before final pixels/input. WebP lossless transforms also require image-sized workspace. | Substantial codec/build/security maintenance; not a routine thin adapter. No demonstrated universal 20MP/128MiB guarantee. Do not silently reject valid progressive 20MP images to fit memory. |
| Streaming PNG verifier | Stream zlib inflate, enforce exact expected row/pass lengths, validate filter bytes/unfilter rows, validate palette indexes, process Adam7 passes and discard reconstructed rows. Keep CRC/end/order checks. Two rows at 8192×8-byte RGBA16 plus DEFLATE window are small. No full canvas buffer is necessary. | Feasible standalone improvement with no heavy dependency, but alone leaves JPEG/WebP incomplete. Exact decompressor/runtime/CPU and cancellation still need actual tests. |
| Worker Images binding + Node sharp | Binding accepts private raw bytes, supports decode/re-encode without a public URL; decoder work is performed by the Images backend. Node can force strict full decode through sharp, not `.metadata()`. Current installed Miniflare implements local Images binding through sharp, so actual local workerd can exercise it. | Recommended narrow practical route, with a new explicit binding and host-dependent acceptance. |
| Separate native validation service/container | Full native codecs with a memory budget above Worker limits, explicit concurrency/time budget, private service authentication. | Feasible fallback if Images cannot meet strictness/all-frame behavior; adds a new deployed service and operational surface. Not the first choice. |

Memory figures are arithmetic inferences from the examined source, not measured WASM peaks or claims about an unexamined pinned npm release.

**Worker constraints.** Official limits count JavaScript and WASM together against 128MB per isolate, shared by concurrent requests; CPU allowance depends on the plan. Per-request wall deadlines do not establish CPU or peak-memory safety. The current repo contains no configured image-decoder CPU/budget proof. A WASM prototype would need isolated concurrent maximum-case tests and real UAT resource-limit evidence, not a small-fixture pass. [Worker limits](https://developers.cloudflare.com/workers/platform/limits/).

**Concrete local feasibility probe.** `raw/image-binding-options-probe.mjs` creates only a temporary local Worker/config; it changes no production source/config or cloud resource. Final Wrangler 4.156.2 / Miniflare 5.20261102.0-beta: genuine PNG 200; CRC-valid corrupt-DEFLATE PNG 422; genuine 5000×4000 three-channel4:4:4 progressive JPEG 200, 235077 input bytes, 86ms local wall time. Results are in `raw/image-binding-options-probe.json`. The helper drains the output stream to force processing. No hosted CPU, decoder strictness or provider-memory claim follows from local wall time. Installed source evidence: `node_modules/miniflare/dist/src/index.js` functions `imagesLocalFetcher`/`runTransform` use native sharp outside the Worker isolate.

**Important animation limit of this probe.** Current local Images emulator constructs sharp without `animated:true`; its animated WebP output has one frame even when `anim:true` was requested. That is not all-frame validation. The implementation must explicitly decode each bounded PNG/APNG/WebP frame, or use a provider path whose all-frame behavior is proved with a corrupt later-frame test. One robust WebP approach is extract each already-bounds-checked ANMF bitstream, wrap it as a complete still WebP with the required VP8X/ALPH envelope, and validate sequentially. Node can iterate native decoder pages with strict failure handling. Total decoded-work/animation policy needs an explicit frozen criterion; do not introduce an implicit smaller canvas cap or silently drop animation compatibility. Cloudflare documents animation limits by the sum of frame areas and supports animated WebP input/output; local emulator behavior is a separate fact. [Images limits/formats](https://developers.cloudflare.com/images/get-started/limits/).

**Proposed implementation order.**

1. Freeze an additive backend criterion: current byte/canvas caps unchanged; strict compressed-pixel verification at upload and finalization; every supported frame verified; define the existing 20MP decoded-work meaning for animation explicitly. Known corrupt payloads must return 422, decoder absence/outage must return 503 without claiming invalid user bytes. No unverified/container-only fallback.
2. Introduce `ImageVerifier.verify(bytes, expectedType, dimensions)` and inject it through `createApp`; runtime Node constructs a native driver, runtime Worker constructs a binding driver. New Worker binding name `IMAGE_VERIFIER` avoids colliding with the existing R2 binding `IMAGES`. Do not import native sharp from the Worker graph. Pin the currently inspected native dependency explicitly if selected; root owns package/lock coordination.
3. Worker driver calls a real `.output()` operation and fully drains its result; `.info()` alone is inadequate. Send private bytes directly over the binding, never a public URL. Preserve original stored bytes/hash/projection unless root explicitly selects canonical re-encoding. Validate all frames, not merely a thumbnail/first-frame shortcut. Node driver uses strict `failOn:'warning'`, explicit pixel/channel limits and full streamed decode, not metadata-only. Metadata precheck still protects input size/caps, and full decoder must agree on type/dimensions.
4. Keep verification before permanent storage/card/version/event/receipt effects. Preserve current lock order/current access at final effects. Recheck original staging hash/state/access at finalize; provider latency is bounded and transaction rollback must remain observable. Do not conflate an upstream service outage with malformed-image 422. Missing verifier fails closed before staging where appropriate.
5. Test actual mounted Node and actual workerd local binding: corrupt DEFLATE with valid CRC; corrupt JPEG/WebP entropy with intact containers; corrupt later animation frame; truncations; palette/Adam7/16-bit PNG; progressive4:4:4 and CMYK JPEG; WebP alpha/lossless/animation; all exact caps; 20MP valid cases; repeat/concurrent verification; provider failure/timeout/cancel/revoke/purge interleavings; no partial storage/DB effects. Record bundle provenance, peak native/WASM/JS memory and CPU limits honestly.
6. Complete local source/build/tests and independent review; deploy UAT only in the parent release order. Hosted binding availability, strict corrupt-stream rejection, all-frame behavior, private-byte processing, final resource usage and unavailable-provider behavior remain explicit UAT checks. Local emulation cannot replace those checks.

The binding is an additional billed service and configuration dependency, but it avoids a new public media URL and the Worker pixel-memory ceiling. No cloud account state or plan availability was queried. [Binding raw-byte/full-operation semantics](https://developers.cloudflare.com/images/optimization/binding/). Sharp documents strict invalid-pixel handling and limits; metadata explicitly avoids compressed pixels. [Sharp constructor](https://sharp.pixelplumbing.com/api-constructor/), [metadata limitation](https://sharp.pixelplumbing.com/api-input/#metadata).

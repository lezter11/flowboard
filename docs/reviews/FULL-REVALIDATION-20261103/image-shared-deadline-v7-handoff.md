**Why and options.** A Flowboard image may spend time reading its private staged bytes before checking pixels. Starting a fresh timer at each step can accidentally add those timers together. One shared absolute deadline prevents that addition while allowing a valid complex JPEG to use unused time from another phase. The former3s JPEG-only cutoff was stricter than the8s complete preflight budget. This revision removes that separate cutoff; it does not make the total request deadline longer. The bounded baseline/progressive comparison in `image-runtime-resolution-v6.md` showed no baseline performance advantage, so supported progressive formats are retained.

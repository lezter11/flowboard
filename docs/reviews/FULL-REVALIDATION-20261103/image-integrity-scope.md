# ATT-02 bounded container repair — implementation scope

This is builder evidence under `criteria/image-integrity.json`, not feature approval or a full image decoder.

The reproduced defect was concrete: a 24-byte PNG header returned 200 from upload, 200 from finalize and created 1 saved image. The expanded pre-repair probe also accepted frame-only JPEG and canvas-only WebP. Complete-container checks now reject these, truncated chunks/segments, missing required image sections/end markers, invalid lengths/order/fields and selected malformed structures. PNG additionally verifies every chunk CRC and the zlib stream header. JPEG validates supported 8-bit Huffman frame/table/scan envelope, including progressive scans. WebP validates exact RIFF bounds/padding, still/animated frame envelopes and VP8/VP8L payload headers. Unsupported arithmetic/lossless/hierarchical JPEG structural variants fail closed.

The parser scans at most the existing 10MiB input cap, allocates no decoded pixel buffer, performs no decompression, and never sizes allocations from chunk declarations. PNG CRC uses one fixed 256-entry table; JPEG component/table collections have fixed format bounds; WebP tracks only four known optional chunk names. Dimension 8192 and 20MP caps, staged digest/length, markup/MIME rejection, attachment cap, private delivery and current access checks are retained. Finalization rechecks old persisted staging bytes and maps validation errors to 422 before permanent storage, attachment, board version or audit effects.

**Residual boundary:** CRCs, segment markers and RIFF sizes are not proofs of compressed pixel-stream decodability. PNG DEFLATE/inflated scanline semantics, JPEG entropy reconstruction and VP8/VP8L pixel entropy are not decoded. Correct-envelope corrupt entropy can still pass this validator. Ancillary metadata semantics are not exhaustively interpreted. No claim of complete decoder fidelity, metadata sanitization, re-encoding or malicious-codec resistance is made. Independent feature review must explicitly decide whether this meets the current acceptance; if full decodability is mandatory, ATT-02 remains open and needs an agreed Worker-compatible bounded decoder/re-encode design.

Genuine compatibility fixtures were generated offline using already-installed sharp/libvips and img2webp. Static bytes are versioned; production does not import those tools or acquire dependencies. An offline independent pixel decode establishes that the fixtures themselves are real images. Node mounted handlers and actual local workerd with local R2 emulator exercise stage/upload/finalize/private content/thumbnail and outsider denial. These checks do not prove hosted R2 durability, production isolation, browser rendering or maximum-payload performance. Parent must repeat verification with the final dependency/source manifest and obtain fresh independent review before UAT.

## Why and options

For Flowboard, the release proof must follow the same Worker bytes from the reviewed build to UAT, just as a saved card must retain the version teammates actually reviewed. Uploading the prepared Worker with `--no-bundle` avoids a second compiler run and makes hashes meaningful. Rebuilding on upload is convenient but adds another unverified artifact; a completely reproducible second build would be an alternative only if its bytes were compared before sending.

A fresh empty candidate directory is a small operational cost that avoids importing a developer's ignored dotenv files and old build products. Stronger helper validation would reduce dependence on operator discipline but changes the held review target; root has chosen bounded execution preconditions for this release.

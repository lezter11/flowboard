# Independent backend/transport source trace

This is a review of the implemented HMCP-05 API phase, not a UI/provider or deployment approval. Product implementation is authored by Architect and builders; this reviewer authored only independent review artifacts/tests. Frozen acceptance is `backend-criteria.json`. Final command outcomes and the passing/failing review record, rather than this narrative alone, determine closure.

## Actions and reachable paths

1. **Browser authorization.** `http/app.ts` mounts `routes/hosted-oauth.ts`. Issuer/resource come from `services/hosted-mcp-config.ts`, not caller Host/forwarded headers. Public client registration accepts only the hosted Claude callback and none authentication. `resolveHostedClient` bounds CIMD to canonical HTTPS claude.ai non-root URLs without credentials/port/query/fragment, manual redirect mode,3-second signal and32KiB JSON. Metadata name remains explicitly unverified. The authorize handler validates exact client/callback/resource/code/S256/challenge and known scopes, then stores an opaque request hash/browser-binding hash and sets an HttpOnly/Lax browser cookie. GET cannot issue a code.
2. **Consent and browser identity.** The OAuth module reads its own cookie session via `getSessionWithUser`; bearer credentials never substitute. `describeHostedAuthorization` locks request and live session, binds actor/session, rotates the CSRF hash and pages100 eligible projects. It reveals capability scopes plus truthful continuing-access/lifetime fields. `decideHostedAuthorization` requires exact Origin, browser binding, actor/session and current CSRF, then locks current project authority and serializes the20-connection cap. Callback comes only from stored validated state. Allow/deny consumes the request and immediately redacts residual state/session/CSRF/browser binding; a session replacement cannot reuse reviewed consent. No membership or board grant is inserted.
3. **Code/refresh/revocation.** `adapters/hosted-oauth.ts` uses opaque32-byte credentials and hashes them at rest. Transactions acquire connection UPDATE before code/refresh UPDATE, compare exact client/resource/callback/PKCE before mutation and then lock current project authority. A consumed correctly bound credential returns invalid_grant as a transaction result after revoking its family, so revocation commits. Wrong-client attempts return before that revocation. Unexpected issuance failures roll back consumption and partial credentials. Refresh leaf uniqueness and root lock prevent forks; access expiry is capped by the absolute family bound. Revoke/disconnect changes the root connection; every later access lookup joins that root.
4. **Protocol and private authority.** Exact POST/GET/DELETE/OPTIONS methods are registered before ordinary middleware, with an exact-path ALL fallback preserving unsupported-method policy. `routes/hosted-mcp.ts` validates canonical URL/Host and explicit Origin, handles public CORS preflight without cookie credentials, verifies OAuth before SDK parsing and applies connection-keyed protocol/create counters. A request-local operations client calls only the existing capability allowlist. `http/hosted-mcp-context.ts` binds the new actual Request object to principal+pool in a private WeakMap; headers, clones, serialized bodies and environment strings cannot create the identity. Authorization/Cookie headers are stripped. `middleware/auth.ts` installs this private machine principal while retaining OAuth rejection on ordinary external REST/session/admin/PAT routes. No OAuth principal is looked up or issued as a PAT.
5. **Current authority and one effect.** Directory SQL restricts the selected project before pagination and binds cursors. Board list/metadata/search handlers take existing live workspace/membership/board-grant locks and construct narrow projections. Create takes OAuth connection/access SHARE locks, actor/grant/assignee locks and writable project/board context before the receipt/card/activity unit. Receipt key is stable connectionId+operationId, with a separate OAuth namespace; semantic input is normalized and excludes only transient structure revision. Replays reauthorize before returning minimal identifiers; changed input conflicts. Activity records the human actor, safe connection ID and operation hash, never a bearer. Nested dispatch reuses the parent's pool, and verification releases its queries before acquiring the child's transaction, avoiding the Worker's sole-connection reentrancy deadlock.
6. **Bounds and real lifetime.** `services/hosted-mcp-transport.ts` admits one128KiB/depth32 JSON-RPC message, validates media negotiation, uses a fresh SDK server per request and closes after actual JSON/tool work settles. Already-aborted and subsequently aborted bodies are handled; declared/streamed oversize refuses without awaiting uncooperative cancellation. `middleware/hosted-oauth-body.ts` runs only exact OAuth/decision POSTs before generic buffering, enforces16KiB raw bytes and a cancellable deadline, privately caches text and preserves handler/session/Origin semantics. Its timeout tracks real downstream work rather than closing a pool under a transaction. `runtime/worker.ts` combines image/MCP lifetimes with rejection-safe settlement before pool closure; without execution context it awaits closure.
7. **Retention and operations.** `services/hosted-oauth-cleanup.ts` is a real scheduled job. It preserves complete retained code/refresh families, keeps terminal identity for seven days after the conservative terminal/last-use anchor, deletes orphan expired requests, redacts residual request state and preserves live/pending clients. Four stages claim25 top-level records by default, at most100, with SKIP LOCKED and a5-second statement timeout in one transaction. Cascading family deletion can involve more child rows; no total child-row, storage-capacity, exact deletion-time or production throughput guarantee is claimed. Scheduler errors roll back this transaction, continue later jobs and report safe job names.

## Why and options

For Flowboard, a connector permission is an additional limit on an existing person: selecting Website does not grant a hidden Website board or access to Operations. A saved receipt remembers one earlier create, and cannot restore permissions after a board grant or membership is removed. Reusing the existing SQL authority and transaction is simpler than a second REST proxy, PAT conversion or duplicated card service. Its cost is a larger shared dependency/review scope and strict lock/pool discipline; the independent tests deliberately challenge those boundaries.

## Findings retained and resolved

- Persistence was absent from the original consent response. Explicit offline/lifetime fields repair it; independent native Worker browser-API tests check the fields against conditional refresh issuance.
- Ordinary middleware buffered OAuth children before their16KiB/deadline guard. Original probe and first failed target remain; the early guard plus genuine createApp tests repair it.
- An already-aborted protocol signal was missed after queued verification. Original probe remains; both service and mounted queued-verification tests repair it.
- Oversize cancellation could retain work on a never-resolving source cancel promise. The final repair makes both cancellation branches nonblocking; direct and mounted declared/streamed regressions are independently executed.
- The first full API gate failed53 inventory assertions because four real protocol methods were handled only by ALL middleware and new workflows lacked valid matrix factories. The new explicit registrations and genuine registration/PKCE/browser-bound fixtures repair coverage. Existing REST cells remain; protocol401/405/204/JSON-RPC semantics have their own assertions. Consent attempts intentionally consume rate counters even on rejection, so those counter effects are separately recorded while all domain tables/sequences/storage must stay unchanged. Public preflight is not counted as a seventh PAT capability.

## Rejected candidates and bounded evidence

- Wrong-client replay does not revoke a victim family: source compares bindings before the revocation branch and independent tests preserve the successor credential.
- Deleting an expired client while consent is pending was a policy inconsistency in an earlier snapshot. Both current registration cleanup and scheduled cleanup now exclude live pending requests; retained history is not suppressed.
- Archive is reversible read-only retention, not membership revocation (`FEATURE_SPEC.md` section3). Known-ID reads of retained metadata do not by themselves establish unauthorized disclosure; actual writes/replays require writable project/board context. Board-grant or membership removal does deny later reads/writes/replay, as exercised independently.
- Global bearer denials can retain documented API error envelopes before OAuth-owned processing. This never admits bearer/cookie fallback; OAuth-owned grants/errors and exact MCP JSON-RPC responses have their proper separate wire contracts.
- All CIMD fetch restrictions are source/injected-fetch evidence; no live client document, provider credentials, internet advisory scan or real hosted sign-in was probed by this review. Installed versions and SDK behavior are checked locally; no advisory-clean claim is made.

## Integration contract and limits

Pages must preserve the canonical public Request URL through its API service binding. Existing API_ORIGIN HTTP fallback rewrites the URL to the Worker host and the MCP host check correctly refuses it. Caller-controlled forwarded headers must not be used to bypass that boundary. The extra actual `startNode` socket probe preserves the public URL with an absolute-form HTTP/1 request target through a local proxy boundary; it proves actual Node OAuth/protocol/create/replay and external REST refusal, not general unconfigured TLS termination.

UI must use the latest CSRF returned by project paging, render client metadata as unverified text, disclose conditional continuing access and treat null lastUsedAt as unavailable rather than inventing usage history. UI/Pages/safe-next/browser Google/Claude acceptance remains mandatory after backend approval. Future backend changes for that phase require fresh affected-source review and updated downstream bindings.

Performance is bounded by explicit sizes, windows, SQL deadlines and measured local command outcomes; no free-tier capacity, hosted latency/CPU or Hyperdrive health claim follows. This review does not approve UAT/production or silently reapprove all historical98 feature records. No user action is required while the backend gate runs.

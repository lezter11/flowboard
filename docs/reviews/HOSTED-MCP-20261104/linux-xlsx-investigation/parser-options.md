# XML parser options for the XLSX import bottleneck

Research snapshot: 2026-11-04. This is a parser-selection note, not a benchmark or an approval to change the import path. The incident profile and constraints are supplied by the task: Flowboard pins `fast-xml-parser` 5.11.2, uses validator plus ordered parser and an app-level strict decoder, and has a 1 s total budget; legal 200-row workbooks with 20 KB escaped fields can approach 20 MB XML. The user's local 0.75-CPU ARM64 pressure run is not known to match hosted CI hardware or quota. No throughput claim below is measured for Flowboard.

## Candidates

| Option | Fit and tradeoff |
|---|---|
| **Patch/vendor the narrow FXP hot path (preferred first experiment)** | Keeps the current `XMLValidator` + ordered-object output and therefore minimizes semantic changes to the decoder. FXP 5.11.2 is MIT and explicitly released with a `Uint8Array` UTF-8 fix; the source is pure JavaScript and the project supports browser and Node usage ([release](https://github.com/NaturalIntelligence/fast-xml-parser/releases/tag/v5.11.2), [README](https://github.com/NaturalIntelligence/fast-xml-parser/tree/v5.11.2), [license](https://github.com/NaturalIntelligence/fast-xml-parser/blob/v5.11.2/LICENSE)). A narrowly targeted no-entity fast path or entity-name predicate change is easier to compare against existing behavior than replacing validation and tree construction. Keep the exact patched dependency/source pinned, retain entity expansion bounds and malformed XML checks, and rerun security and semantic fixtures. A fork/vendor copy adds maintenance and CVE/cherry-pick responsibility; an upstream fix avoids the fork but has no guaranteed release timing. **No measured improvement is established here.** |
| **`saxes`** | Strong XML 1.0/1.1 and namespace well-formedness claims, evented parsing, only five predefined entities by default, and no automatic custom DTD entity expansion ([project documentation](https://github.com/lddubeau/saxes/tree/v6.0.0)). It is pure JS and designed for Node while documenting browser/CommonJS compatibility. However, its owner archived the repository on 2025-12-31, so it does not satisfy a maintained-parser requirement ([archive status](https://github.com/lddubeau/saxes)). Its SAX events also require Flowboard to build its own ordered tree/record extraction and test equivalent scalar/attribute handling. The parser does not thoroughly validate DTD contents; treat DTDs as disallowed by the import contract if adopting it. |
| **`sax` (`sax-js`)** | Lightweight pure-JS event parser; strict mode, optional namespace support, and strict predefined-entity handling are documented ([README](https://github.com/isaacs/sax-js/blob/main/README.md)). It remains actively developed in the upstream repository, but its own docs warn strict mode is not fully strict XML well-formedness, so it is a weaker validator replacement than `saxes`. Events still require custom tree/scalar conversion. It does not offer DTD validation or general custom entity expansion; fail closed on `doctype` rather than treating strict mode as proof of DTD safety. There are no formal GitHub releases to use as a release cadence signal ([releases page](https://github.com/isaacs/sax-js/releases)). |

## Recommendation and limits

The latest published stable FXP release verified here is **5.12.0, released 2026-11-03** ([release](https://github.com/NaturalIntelligence/fast-xml-parser/releases/tag/v5.12.0)). The relevant hotspot is `validateAmpersand`, which is called by the validator whenever it encounters `&` in text. In the current upstream validator it still executes `xmlData[i].match(/\w/)` inside the named-reference scan, with the 20-character count bound; this is the profiled named-entity predicate, not the separate XML tag/attribute `isName` helper ([current validator source, function lines 438–456](https://github.com/NaturalIntelligence/fast-xml-parser/blob/master/src/validator.js#L438-L456); [5.12.0 validator source, same function location](https://github.com/NaturalIntelligence/fast-xml-parser/blob/v5.12.0/src/validator.js#L438-L456)). The v5.12.0 release notes contain no validator/entity-reference optimization. Thus no released upstream fix for the profiled loop is evidenced here; a routine 5.12.0 bump may still be assessed for unrelated fixes, separately from the performance claim. No throughput conclusion follows from source inspection.

Benchmark the private FXP patch in the existing controlled **0.75-CPU ARM64 local pressure harness**, with validator and ordered-parser timings separated. Then measure on hosted CI independently if that environment's actual quota/hardware is relevant and available; do not call the local harness equivalent to CI. If the patch clears the 1 s target with margin across repeated runs, prefer it over a parser replacement and document ownership of upstream security fixes. If it does not, prototype an event parser (likely `sax-js` only if its strictness gaps are explicitly compensated, or reconsider archived `saxes` only with acceptance of maintenance risk); tree construction and semantic equivalence will be material work. Do not infer throughput from upstream claims or another runtime.

For either path, Flowboard's own byte decoding should remain authoritative: explicitly decode supported UTF-8/UTF-16 input before passing a string to the parser, since parser support for XML encodings is not established by these docs. Define and test policy for XML declarations, namespaces, numeric character references and XML 1.0 scalar validity. Reject `DOCTYPE`/external entity constructs at the import boundary unless product requirements specifically need them; parsers' lack of fetching is not, by itself, evidence that arbitrary DTD syntax is rejected. A SAX replacement must also prove the same ordered element and scalar semantics consumed by the current strict decoder. FXP 5.11.2 is MIT; current sax-js `main` identifies its license as Blue Oak Model License 1.0.0; saxes is ISC ([FXP license](https://github.com/NaturalIntelligence/fast-xml-parser/blob/v5.11.2/LICENSE), [sax-js current license](https://github.com/isaacs/sax-js/blob/main/LICENSE.md), [saxes license](https://github.com/lddubeau/saxes/blob/master/LICENSE)). License conclusions are version-specific; verify the exact pinned revision before adoption.

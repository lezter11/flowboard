# Flowboard quick security audit, November 15, 2026

**1 High, 2 Medium, 1 Low.** This quick audit targeted the application currently served in production. It used signed-out, read-only public requests and exercised write/race cases only with synthetic identities on disposable PostgreSQL. No changes were made to application source or deployed services.

## Findings

| ID | Severity | Source | Reproduction and impact | Suggested fix | Confidence |
| --- | --- | --- | --- | --- | --- |
| FB-QA-01 | High | `apps/api/src/http/routes/google-auth.ts:27,178,209,229` | Send two profiles through the mounted Google OAuth callback with the same verified email and different Google subject IDs (`sub`). Stub only Google's responses and use real PostgreSQL and Flowboard sessions. Both sign-ins issue sessions for the same local actor. This is an account takeover path if a different Google account can present a recycled or reassigned address. Live Google address reuse was outside the test. | Bind accounts to the verified Google issuer and stable subject. Migrate existing users with proof of account continuity. Do not silently bind a new subject to an existing account based on email. | Confirmed app behavior, provider precondition external |
| FB-QA-02 | Medium | `apps/api/src/adapters/cards.ts:389,412,435` and `apps/api/src/http/routes/cards.ts:164` | Luna paused a real mounted card GET around the database queries. One request returned a link after the grant was revoked and committed, then a fresh request returned 404. Another fetched the old row before the requester had a grant. After the owner removed the link and granted access, the same response returned the removed URL and a fresh response showed no links. Both probes reproduced independently. | Read protected card data with authorization in the same database snapshot, and serialize sensitive reads against grant revocation where required. Add both interleavings to integration coverage. Google Drive still enforces its own sharing settings. | Confirmed locally with synthetic data and deterministic timing |
| FB-QA-03 | Medium | `apps/api/wrangler.jsonc:3` and `apps/api/src/runtime/worker.ts:71` | Anonymous plain HTTP on the direct production Worker hostname returned 200 for `/health/live` and MCP discovery, and 401 for `/api/v1/session`; none redirected. A client configured with an HTTP API URL could send a bearer credential in cleartext on the first request. All probes were unauthenticated. The canonical Pages hostname redirected HTTP to HTTPS. | Check for intentional clients of the direct hostname, then remove that exposure where possible. Otherwise use an HTTPS-only ingress, enforce TLS for clients and reject plaintext requests before authentication or application logic. | Confirmed plaintext listener, credential impact conditional |
| FB-QA-04 | Low | `apps/web/public/_headers:1` | HTTPS `/signin` served the expected CSP but no `Strict-Transport-Security` header. An HTTP request to the Pages hostname received a 301 to HTTPS. The absence of an explicit HSTS response weakens browser downgrade protection when an applicable inherited or preload policy is absent. Browser preload behavior was outside this quick audit. | Configure HSTS on the canonical app hostname and verify its browser behavior. | Confirmed missing response header |

## Dependency advisories

Sanitized `npm audit --json --ignore-scripts` against the committed lockfile returned exit 1 and flagged two Moderate packages and one Low package. The result counts packages, not distinct advisory records. There were zero High or Critical packages. The proof below applies to the advisory paths checked in this audit.

- `hono` 4.13.14. Reproduced the encoded line-terminator wildcard skip on the library's `RegExpRouter`. Flowboard's mounted API explicitly uses `TrieRouter`, and all 15 malformed-path probes kept middleware and returned 401 or 404 with no data. Source search found no uses of the cited mount, form-validator, CSS helper or Hono CSRF paths. [Router advisory](https://github.com/advisories/GHSA-h7mg-cq63-vhpq)
- `@hono/node-server` 2.1.5. Used by the optional Node server. The deployed Cloudflare Worker uses a separate entry point. The reviewed Node source had no WebSocket upgrades. Node reverse-proxy configurations were outside scope. [Path advisory](https://github.com/advisories/GHSA-jpvv-r467-5p4w), [WebSocket advisory](https://github.com/advisories/GHSA-qv5m-9pm6-hqp3)
- `fast-xml-parser` 5.11.2. The reported path requires nondefault `stopNodes`, which the XLSX importer does not enable. Keep any upgrade paired with the existing XLSX parser-budget and bundled Worker regressions. [Parser advisory](https://github.com/advisories/GHSA-474x-hrwr-fgx4)

## Evidence and limits

- Cloudflare production Pages `51c03bd3-8483-4b93-9484-4464e4510c24` identified source `7cc0059d8456a5db5848fe49eebf4b904f1dd4b2`, with Worker `5e0695d0-f47a-444a-9640-7b350c19505d`. The clean local checkout at `82fbb1f1c0a2ffdedce1e16b80db03d53987475e` differs only in release documentation. All 635 tracked application, database, package and script hashes matched after testing.
- 628 API tests passed, zero failures or skips. Suites covered mounted auth and cookie mutations, Google sign-in state, hosted OAuth/MCP, link projection and board/image access. The generated receipts report 520 authorization and 307 cookie-mutation scenarios, including internal checks and positive controls. Those scenario counts overlap in scope and are not additional unique test counts. Five link/Pages proxy tests passed separately.
- The direct OAuth identity-switch proof and Luna's two race reproductions passed against disposable PostgreSQL 17.11 on loopback port 55696. The local repro script for Drive uses the existing synthetic lifecycle fixture. Its absolute import paths refer to the isolated checkout used for the audit.
- 17 signed-out read-only hosted probes covered session/card refusals, administrative endpoint refusal, MCP metadata, cache directives and HTTP/TLS behavior. No authenticated production Google, Claude or Drive flows, load tests or exhaustive route-by-role and race coverage were attempted.

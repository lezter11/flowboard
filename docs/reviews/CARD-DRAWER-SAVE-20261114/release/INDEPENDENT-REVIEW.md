## Source and findings

- **Resolved, scope leak from Round 1.** `apps/api/src/http/routes/cards.ts:166` requests link columns only for session authorization. `apps/api/src/http/middleware/auth.ts` assigns PAT and privately dispatched hosted machine principals the token authority type and `apps/api/src/http/middleware/token-policy.ts` denies machine PATCH. A mixed credential probe confirmed that a cookie does not upgrade such a machine request. Create and move SQL never select the link column, move undo calls the same move adapter, and trash/restore's explicit projection at `apps/api/src/adapters/trash.ts:109` selects no links. Board snapshots, card pages and search omit the field. Generated `CardDetailResponse`, `PatCardDetailResponse`, `CardPatchResponse`, `CardResponse` and `MinimalReplayResponse` agree.
- **No open mandatory application defect found.** Session detail checks current active card state, project role and board grant. Writes follow Origin checks and existing locks on ownership, membership, grant, writable context and card row before comparing the supplied version. Board grants apply to results and receipt replay. A viewer can GET saved links but cannot PATCH. Sibling-only access and a revoked grant return 404 and expired sessions return 401. Two different lists submitted at the same version produce one committed list and one 409. Retrying an identical request after an uncertain response returns only identifiers and versions. Activity records link counts and never link text.
- **Migration and older code.** File and embedded paths both apply `0029` after `0027` without deferred binary upload migration `0028`. Explicit-column creation and older writes retain the additive column. The unchanged purge UPDATE also fires the new database trigger and clears links. Trash and restore retain files' links under the same card lifecycle while suppressing them from unrelated mutation responses.
- **Validation and bounded behavior.** The shared schema permits up to ten ordered unique URLs by normalized spelling. It rejects lookalike hosts, credentials, ports, URL parser dot-segment normalization and parameters outside a bounded allowlist. Two differing sharing URLs for the same Google file may be stored as separate URLs. Backend and drawer make no preview request. The browser test observed an explicit Google navigation without opener or referrer. Request, URL, label and list caps bound normal input. The DB bounds array shape and count; the application enforces links' internal fields and format. Existing GET authority checks are repeated but do not form a single database snapshot. No hosted account, production data, or online package advisory scan was used.

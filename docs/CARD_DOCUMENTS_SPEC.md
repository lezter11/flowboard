# Private card documents

This branch archives the local prototype from the November 14, 2026 Flowboard worktree, based on `01474948a2d9f3f49393c93e566f000167a84f5b`. It preserves the upload source, migration, scanner package, contracts, tests and the feature-flagged drawer. The user deferred uploads while using Google Drive links on cards. Do not deploy or apply the prototype migration as part of the Drive-link release. Reconfirm migration order, scanner readiness, private storage cleanup, and independent review before resuming hosted uploads.

## Prototype scope

Add a PDF, Word (`.docx`), or Excel (`.xlsx`) attachment to a saved card. An Owner, Project Manager or Member with access to the card’s board can upload. Anyone who can view the card can download an accepted attachment. Removal is limited to the uploader and authorized project administrators with write access. Apply current board access checks to upload, list, download and removal. Existing card trash and restore rules cover document metadata and bytes, with storage cleanup after the restore window. An Excel attachment is a download. The separate Excel card import turns rows into cards.

The drawer shows Checking until processing finishes, then the file name and actual size. Failed files give a short explanation and a retry where applicable. An empty section gives editors one Add document action and stays hidden for viewers. The initial limits are 1 MiB per input and ten accepted documents per card. PDFs have a 40-page limit and reject encryption, forms, embedded files, and active content. Word and Excel support the modern macro-free formats. Legacy `.doc` and `.xls`, macro-enabled packages, encryption, external connections, embedded objects and unsupported package parts are rejected. Test representative team documents before increasing limits or expanding the Office feature profile.

The Office profile supports ordinary Word text, tables and styles, and Excel worksheets with common calculations on cells within the workbook. It rejects embedded Office media, charts, custom XML, active Word fields, and formulas outside the supported local subset. Office archives are limited to 32 file parts and 8 MiB of total expanded data. The XML preflight also bounds attributes, namespace declarations and nesting before building the parsed tree. Files can be smaller than 1 MiB on disk and still exceed these limits.

## Drawer acceptance

- Show Documents on an active, saved card when the capability is available. Give an editor one Add document action, with the size and file-type limit next to it. A viewer sees accepted files only. Hide the empty Documents section for a viewer.
- Give each accepted document a name, a stored size and a download action. Ask before removing it. Re-check current permissions after the card or project changes. Clear protected results if the user signs out or loses access. Download through the authenticated origin with an attachment response and the verified format. The browser downloads these files without an inline preview.
- Keep an upload's Checking state independent of card edits, image uploads and comments. A timeout can occur after a successful save. In the open drawer, retry the original file with the same idempotency key so one action produces one attachment. Replacing the file starts a new action.
- Test clean files of all three formats, MIME/extension mismatch, disallowed contents, archive expansion, oversized input, unavailable scanner, denied role, removed board access, retry after response loss, and a card moved to trash during checking. Check both a narrow phone layout and a desktop layout.

## Processing and privacy

1. Authenticate the session, enforce CSRF and limits, and verify the card's current role, board and state. Bound the request before buffering. Treat the filename, claimed file type and bytes as untrusted. Keep incoming bytes in bounded request memory and the scanner's isolated temporary storage.
2. Process in a separate, resource-limited service under Flowboard's control. For PDFs, scan the input with ClamAV before qpdf, check the structure, try lossless compression, and scan the exact output. For Word and Excel, first enforce bounded ZIP and XML structure, package type, relationship and active-content rules, then scan the exact accepted archive with ClamAV. Keep approved Office bytes intact because these formats already use ZIP compression and rewriting can damage formatting or formulas. Verify and show the actual stored size and SHA-256 digest where applicable.
3. Only accepted output can become a card attachment. Scanner and response failures leave files unavailable. Treat stale signatures as a scanner outage when the hosted readiness guard is wired. Record a durable storage reservation with a generated key before writing accepted bytes to private object storage. Failed reservations are eligible for cleanup. Pending bytes are unavailable from the download route.
4. Before publishing, acquire the same card and grant locks used by card operations, recheck the uploader and card, verify the staged object's identity, and commit metadata, the operation receipt and safe activity together. A retry with the same key cannot add a duplicate. Confirm the object is referenced before sending success. Downloads use fresh session and board checks, attachment-only disposition and a no-store cache policy. Never log file contents, scanner internals, storage keys or secrets.

This keeps document processing outside the request runtime. A Cloudflare Container could host the Linux processor on Workers Paid. A separate dedicated service is also possible, but its ownership, networking, signature updates and cost must be verified before it receives team files. The local processor and scanner tests are engineering evidence. They do not establish hosted document availability. No public multi-tenant scanning service is selected.

The [portable Linux candidate](../apps/api/src/runtime/document-scanner/README.md) runs the scanner and ClamAV on private Unix sockets and updates signatures in a separate container. The scanner checks the daemon’s loaded signature date and runs clean and malware-detection canaries. Real signature updates, restart behavior and the authenticated path from Cloudflare still require hosted verification. A loopback listener on port 8788 remains available for local tests. The drawer is behind `NEXT_PUBLIC_FLOWBOARD_DOCUMENTS=true`, a build-time setting for explicitly enabled test builds. See the [API contract](openapi.json) for request and response fields.

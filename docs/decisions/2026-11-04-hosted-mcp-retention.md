# Hosted MCP OAuth retention addendum

2026-11-04. Accepted operations repair to `docs/HOSTED_MCP_SPEC.md`, recorded before implementation. Parent delegated the OAuth cleanup service, Worker scheduled-job entry, relevant adapter redaction, undeployed migration0027 indexes and focused tests. No cloud mutation or queue/service addition is authorized by this note.

A spent refresh token is evidence of reuse, so deleting its hash while a connection can still continue would remove a security check. Keep complete code/access/refresh families while their connection identity is retained. Delete only terminal connections after at least seven days following the later of (a) the earlier of absolute expiry or revocation and (b) last use, falling back to creation when unused. The seven days preserve existing bounded card-retry identity and safe audit references. Keeping a family longer than its refresh idle expiry is deliberate; access/refresh handlers enforce expiry independently of cleanup.

Use the existing Worker scheduler and PostgreSQL, one request-scoped pool connection. Each run performs one bounded transaction with four stages: old terminal connection deletion and dependent credentials; expired authorization-request deletion only when no code references it; remaining decided/expired request redaction; expired registered-client deletion only when no live connection or undecided unexpired request uses it. Each stage claims at most25 rows by default (hard cap100), ordered by expiry/retention time and ID with `FOR UPDATE SKIP LOCKED`. Connection deletions cascade credential rows, so the row cap applies to top-level families, not the total size of their children. A five-second PostgreSQL statement deadline bounds a stalled stage and rolls back that cleanup transaction; later scheduled jobs still run under the existing failure-isolation wrapper.

Never delete a request merely because its ten-minute browser window expired when a retained authorization code references it: its ON DELETE CASCADE would erase code reuse evidence. Request state is redacted separately even when the row remains. Immediately after an allow/deny decision, build the callback URL in memory, then clear plaintext state, session hash and CSRF hash, and replace the NOT NULL browser-binding hash with a public all-zero non-credential sentinel. Apply the same redaction to expired/previously decided requests in bounded batches. An active, undecided, unexpired browser request retains its binding.

Add indexes matching the connection retention anchor, live clients' connections, pending client authorization and dirty-request redaction. Existing unique code request lookup, token-family and client-expiry indexes support the other stages. All expiry decisions use the database clock; no exact deletion deadline or storage-capacity claim follows from one scheduled batch. Backlogs drain on later successful scheduler invocations. Failures remain reported, not silently accepted.

Related transport assembly uses a true MCP-work lifetime callback. An HTTP deadline can return while its database work is still settling, so the Worker retains its pool until all reported image/MCP work settles, including failures. Its execution context owns asynchronous closure; callers without that context await settlement. This adds no new job, service or public API capability.

Acceptance: real PostgreSQL tests must prove immediate decision redaction, active-state preservation, retained-family code/refresh reuse detection, complete self-referencing refresh-chain cascade, seven-day retention/last-use guards, cap/idempotence/SKIP LOCKED behavior, active client protection, actual Worker scheduled execution and continuation/reporting when this job fails. Previous component snapshots remain in `docs/reviews/HOSTED-MCP-20261104/backend/round-1` and `round-2`; a new source manifest and fresh review are required.

# Scoped machine operations in the existing API

Status: implementation decision for the isolated MCP repair; acceptance depends on its independent review. Risk: high. Base source62ce05f, acceptance frozen in docs/reviews/MCP-REPAIR-20261103/criteria.json before edits.

An API credential is like giving Claude a key for one job. It must not become the person's master account key. The current implementation admits only six named method/path capabilities and then checks scopes, optional project restriction, the person's current role and the board grant. Routes added later remain denied until deliberately permitted. This contains future UI-route additions without introducing a separate service. The alternative is a dedicated integration namespace with independent principals; that is appropriate for the planned company installation API, but would add product/API work beyond repairing local stdio MCP.

Column discovery uses a metadata endpoint with a runtime projection. A TypeScript interface alone cannot remove extra card properties from JSON; an explicit response object can. Full board snapshots stay session-only. Project restrictions are SQL predicates before pagination, so hidden projects cannot appear in a cursor.

The host supplies a persistent operation ID for creation. The server namespaces its hash by credential and compares the normalized card input, excluding the board revision. A revision is a temporary collision check, not the identity of the requested task. Two parallel deliveries with the same key share a PostgreSQL advisory/receipt lock and produce one result. An optimistic stale-revision failure may be refreshed once using the same key; an unknown network outcome retains the key. Receipt retention is seven days. A durable external-issue identity for daily fleet alerts is a separate future invariant; receipts and title search cannot replace it.

Protected creation holds a shared credential row lock, then existing grant/context/receipt/board locks. A conflicting revoke waits for the protected transaction; a request blocked behind a completed revoke rechecks and fails. Card, safe origin activity and minimal receipt commit together. Audit provenance keeps the human actor plus server-derived credential ID and a hash of the operation ID in `safeChanges.source`; no new migration is needed. Content redaction retains these small origin facts.

New credentials expire after30days by default (up to365) and issuance serializes a20-active-token cap. Infinite legacy credentials remain readable/revocable; they should be rotated for UAT. An enforced per-installation card budget, board-bound company credentials, durable external IDs, remote MCP OAuth and a credential-management UI are future work. Current project-bound tokens can access every board their human can currently access within that project; they are not single-board installation keys.

The compiled MCP binary is a tested distribution target; CI covers it separately from API code. Network requests have a deadline/size cap, reject redirects, validate URL/IDs/dates and emit safe status/code errors. The packed-bin smoke test reuses locked installed dependencies rather than claiming a fresh registry install. No latency benchmark or hosted safety is claimed by local tests. See the repair summary for actual command counts, remaining dependency debt and signed-in UAT steps.

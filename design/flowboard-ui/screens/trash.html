Restore rules

What the 24 hours do and do not do

Deadline: exactly 24 hours after the delete commits, measured by the server.
Restore: returns the card to its previous column with comments and private images intact.
Expired: restore returns a gone state. Permanent purge timing and storage deletion are later scope.
Archived project: archiving does not pause a restore deadline.
Restore is an access event. Owner and Manager can see who restored a card and when; Member and Viewer cannot see the trash surface at all.

Why this is restricted

Deletion is destructive enough to gate

Members can edit cards but cannot delete them in this product. A deleted card contains private comments and images, so browsing trash is limited to Owner and Manager.

UI hiding is not authorization. The API must reject trash reads and restores for Member and Viewer on every request.

Preview note

The countdown uses the browser clock as a stand-in for server time. The state selector is a review aid; it does not change any real deadline.
